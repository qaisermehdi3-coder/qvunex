Cost scales with price: a card at twice the price costs twice as much per token at the same load. A card measured on several hosts is compared at one price, the lowest measured unless you change it.

Bold rows meet your target.

What this is. Qwen2.5-7B-Instruct, vLLM 0.27.1 with default flags, prompts of about 512 tokens (or 2,000, chosen above; only equal lengths are compared) and 256-token answers, 60 s at each load, one run per load. Cost = GPU price x the measured window. Request and token counts were checked against vLLM's own /metrics counters and matched exactly. "First token" is the mean time to first token from vLLM's own histogram at that load.

What it is not. Only measured points are used: nothing is interpolated between loads or carried over to other models, prompt lengths or GPUs. Costs assume the GPU is busy the whole time; idle hours in a real day raise them, and only your own traffic shows by how much.

Raw data, server logs and method: benchmarks/corpus. Same answer from the command line: python3 cheapest.py --p95 8.
